# The figure set

What exists, what is planned, and what in the 2023 thesis each figure answers
to. Captions live in [`README_fragments.md`](README_fragments.md); this file is
about the set rather than about any one figure.

It exists because the count did not. The repository README has said "of a
planned nine" since the set was three, and **the membership of that nine was
never written down anywhere** — not here, not in `notes/decisions.md`, not in
`config/recipes.yml`. Three of the missing ones were named only in passing, in
the module docstring of `src/figures/fields.py`, as figures that would share
the composite's 97 holes. A planned set that is only a number is a set nobody
can check, so the number is reconstructed below and the README now agrees with
it.

Every figure is generated by a module under `src/figures/`, written through the
verified export path in `src/figures/output.py`, registered in
`config/recipes.yml` and committed as a PDF and PNG pair.

**How this file is read by a test, and the one rule that keeps it honest.**
`tests/test_figure_inventory.py` parses the two tables below and checks them
against `figures/` in both directions, so the inventory cannot promise a figure
that does not exist and cannot omit one that does. The distinction between the
two is structural rather than a matter of phrasing:

* a row under **What exists** names a figure **stem in backticks** in its first
  cell, and both `figures/<stem>.png` and `figures/<stem>.pdf` must be there;
* a row under **What is planned** names a figure in **plain prose with no
  backticks**, and must not correspond to a file.

A planned figure therefore cannot be written as a stem, and a built one cannot
be written as prose. The section headings are matched verbatim, so renaming one
fails the test rather than silently switching off half the check. The counts in
the two sections and in the repository README are checked against the tables as
well: this file has already claimed eleven planned figures when the tables said
twelve.

Thirteen. The recipe tier is what `tests/test_recipes.py` does with it:
*continuously* means the artefact is rebuilt and compared byte for byte in the
default suite, *on local* means it needs an input that is not committed and
runs only in the slow tier. Twelve of the thirteen are in the default suite; only `coverage_saturation_2018`
needs an uncommitted input, because it counts granules rather than reading a
derived table.

The two `framework_*` figures are **diagrams**, and they draw from a second
declared vocabulary: `src/figures/diagram.py` holds the shapes the way
`src/figures/style.py` holds the colours. They follow two different visual
grammars, ISO 5807:1985 for the flowchart and Patil, Peng and Leek (2019) for
the reproduction status figure, and the vocabulary refuses a figure that mixes
them.

## What is planned and does not exist

These are the three named in the module docstring of `src/figures/fields.py`,
which is the only place any of them was ever written down.

| Figure | What it would show | Why it is not here |
| --- | --- | --- |
| predictor maps | impervious fraction and rice fraction on the analysis lattice, beside the methane field | not started; the covariate rasters and the lattice both exist, so this is drawing rather than analysis |
| fold map | which cells fall in which spatial block and which province, for both evaluation schemes | not started; it is the figure that would show why a held-out province's interior has no training neighbour, which is currently a sentence in three captions |
| sampling artefact map | where the composite's cell means rest on few soundings, and where the observation days differ most | not started; `ERRATA.md` 7.4 is why it matters — a cell's annual mean is taken over whichever days it was observed on, and those differ by up to 228 days |

Three, so the set is a planned sixteen and thirteen of them exist.

**The README's "nine" could not be reconciled with any of this**, which is the
clearest evidence that the number was never backed by a list. Seven built plus
the two figures added here is nine, but `fields.py` names three unbuilt figures
and the baseline comparison was a fourth, so the planned set was never nine on
any reading. Eleven is the count that follows from what the code actually
names.

**The baseline comparison figure is not on this list, and was cancelled rather
than deferred.** It would have drawn held-out R squared as bars with the
spatial null as a reference line, which reports the finding without showing it.
`observed_predicted` shows the same comparison as a shape, and its panel (e)
carries every model under both schemes and both weightings, which is strictly
more than the bar chart would have held. The two figures added here replace it;
they do not sit beside it. That is why the count went from a planned nine with
seven built to a planned ten with eight.

## The 2023 thesis's figures, and what answers to them

The thesis PDF numbers its figures by chapter — 4.5, 4.6, 4.7 — and the
markdown rendering in `legacy/` numbers them sequentially, 1 through 18. **The
numbers do not carry between the two documents**; `legacy/README.md` records
why. The sequential numbering is used here because it is the one that can be
enumerated from a file in this repository.

| 2023 | Subject | Equivalent here |
| --- | --- | --- |
| 1 | study area | `study_area` |
| 2 | DeepLabv3+ architecture, the PDF's Figure 3.1 | not redrawn, and deliberately: `framework_pipeline` and `framework_reproduction` take its place. See below |
| 3, 4, 5 | urban boundaries, 2000 / 2010 / 2018 | `urban_change`, `landcover_native` |
| 6 | urban expansion trends 2000–2018 | `urban_change` panel (c) |
| 7, 8, 9 | urban boundaries by province | `landcover_regional` |
| 10, 11, 12 | rice distribution, 2000 / 2010 / 2018 | `landcover_native`, `landcover_regional` |
| 13, 14, 15 | urban and rice together | `landcover_native` |
| 16 | XCH4 distribution 2018 | `methane_composite_2018` panel (a) |
| 17 | hotspot analysis | none, and none planned — see below |
| 18 | remote sensing against agricultural statistics | `landcover_regional` panel (b), in part |

Two of the eighteen have no equivalent and are not planned, for opposite
reasons.

**Figure 2, the DeepLabv3+ architecture diagram, must not be redrawn**, and
that is a stronger statement than "not planned". `ERRATA.md` 4.1 records that
Section 3.3 describes a masked autoencoder citing He et al. throughout while
the implementation is supervised segmentation with `nn.MSELoss`, and 3.3
records that the backbone was randomly initialised and then frozen. The diagram
therefore depicts an architecture that was neither described accurately nor
implemented as described, and a faithful redrawing would have to choose which
of the two to be faithful to. The reproduction built no network at all;
`notes/repository-architecture.md` records that decision and the baselines that
forced it. **Two figures take its place.** `framework_pipeline` draws the system
that was actually built, and `framework_reproduction` is about the reproduction
rather than about a network -- it occupies the place in the argument that
Figure 3.1 held, which was to say what kind of thing the study is, without
depicting an architecture that does not correspond to any code.

This is the one row where the two numbering schemes had to be tied together,
because both are cited in this repository: the markdown rendering's Figure 2 is
the PDF's **Figure 3.1**, captioned "DeepLabv3+ Architecture" on page 15.
Verified by extracting that page's text rather than inferred from the section
it sits in.

Figure 17 is a hotspot map whose statistic `ERRATA.md` 6.2 records
as reported without its spatial weights; redrawing it would mean choosing
weights the original did not state and presenting the result as the same
figure. The spatial statistic that *is* reproduced, with its weights written on
the figure, is the Moran's I in `residual_field` panel (c).

Six figures here answer to nothing in the thesis:
`coverage_saturation_2018`, `observed_predicted`, `residual_field`,
`framework_pipeline`, `framework_reproduction` and `albedo_collinearity`. The first reports a coverage
statistic the thesis never gives. `framework_pipeline` depicts a system the thesis
did not have and `framework_reproduction` is about the reproduction itself,
which is not a thing the thesis could have had a figure of.
`albedo_collinearity` answers an objection to a finding the thesis never made.
The other two are the diagnostics a negative result needs, and
the thesis's Figure 4.7 was captioned as one of them —
`ERRATA.md` 1.1 records that its panels are the same embedded image as Figure
4.5(a), so the comparison it claimed to draw was never drawn at all.

## What is in `checks/`

Gitignored. `scripts/verify_figure.py --renders` writes greyscale and
protanopia, deuteranopia and tritanopia versions of a figure there, which is
where a colour decision is checked rather than argued about.
